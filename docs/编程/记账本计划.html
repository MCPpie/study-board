为什么是这个题目
你的卡点是「能写小作业，拼不成程序」。小作业是局部逻辑， 完整程序要管数据、存文件、防崩溃、能反复用。

记账本刚好把这四件事全占了，而且你自己会天天用它—— 有真实用途，才不容易写到一半就扔。

九级阶梯

每一步都必须能跑起来再往下。不许出现「改到一半全崩」的状态。

v0.1
打印一行，跑通环境10 分钟 写两行 print，看到字出现在屏幕上就算过
v0.2
输入一笔，存进列表，打印出来 金额 + 分类 + 日期。先只在内存里，关掉就没了
v0.3
写进文件，关掉重开还能读回分水岭 这是「小作业」和「程序」的真正区别——程序有记忆
v0.4
算本月总额 读文件 → 过滤本月 → 累加
v0.5
列出所有记录，带编号 编号是后面「改」和「删」的入口
v0.6
按分类统计 餐饮 120、交通 30… 用字典聚合
v0.7
输字母不崩溃 用 try/except 接住，提示重输而不是退出
v0.8
数据层与界面层分开架构 把「读写文件」「算总额」抽成函数，主程序只负责菜单。 这一步之后你会第一次感觉到：程序是可以分层的
v1.0
循环菜单，能反复用 不用每次重新打开。跑三次验收：正常输一次、故意输错一次、关掉重开一次

三条规则

这三条是防「卡住 → 拖延 → 放弃」的，不是防懒。

规则 1 卡住 20 分钟必须开口，但要说清三件事 ① 我想做什么　② 我试了什么　③ 报错原文（复制粘贴，不要转述）
不许「放着明天再说」——那是雪崩的起点。
规则 2 问 AI 时，只要三种东西 报错在说什么 / 伪代码 / ≤3 行 的 API 用法。
不要直接要完整代码——那会让你「看起来完成了」，但什么都没学会。
规则 3 每完成一个版本，自己跑三次再给人看 正常输一次、故意输错一次、关掉重开一次。扛住这三次才算完成。

常见卡点预警

① 环境跑不起来
你已经装了 Anaconda 3.9.13，路径 D:\anaconda\python.exe。 不用重装。VS Code 打开文件夹，按运行键就行。

② 文件存了但读不回来
九成是路径问题：程序在哪运行，文件就写在哪。 用绝对路径先跑通，再改相对路径。

③ 想加功能，结果把能跑的改崩了
先复制一份能跑的版本再改。崩了就把旧的拿回来——这是最基本的自保习惯。
